## 2. `ios/Runner/Info.plist` — what was added and why

Every entry below is the iOS counterpart of a runtime permission declared in
`android/app/src/main/AndroidManifest.xml`. iOS **terminates the app** the first
time a capability is used without its usage description, so these keys are
load-bearing:

| Key | Feature that needs it |
| --- | --- |
| `NSCameraUsageDescription` | Barcode scanning for inventory intake (`mobile_scanner`) — mirrors `android.permission.CAMERA`. |
| `NSLocationWhenInUseUsageDescription` | Shop GPS capture + map location picker (`geolocator`) — mirrors `ACCESS_FINE_LOCATION` / `ACCESS_COARSE_LOCATION`. Only *while-in-use* is requested, so no `LocationAlways…` key is needed. |
| `NSPhotoLibraryUsageDescription` | Product / shop photos via `FilePicker.pickFiles(type: FileType.image)` (`product_sheets.dart`). The document-only Excel import (`FileType.custom`, `.xlsx`) uses the document picker and needs no key. |
| `CFBundleURLTypes` → `com.googleusercontent.apps.…` | OAuth callback URL scheme — see §3. |
| `NSAppTransportSecurity` → `NSAllowsLocalNetworking` | The development backend is reached over plain HTTP on the PC's LAN IP (`http://192.168.x.x:8000`, `DevBackendDiscovery`) — the iOS equivalent of `android:usesCleartextTraffic="true"`. Public internet hosts are still ATS-enforced; production URLs must be HTTPS (`EnvConfig.validateProduction()`). |

> Not added on purpose: `NSLocationAlwaysAndWhenInUseUsageDescription`
> (`requestPermission()` only asks for while-in-use),
> `NSPhotoLibraryAddUsageDescription` (the app never writes to the library),
> and the Push Notifications entitlement (see §4).

## 3. Google Sign-In on iOS

`FirebaseAuthService.signInWithGoogle()` picks the implementation per platform
(`googleSignInStrategyFor()` in `lib/core/auth/firebase_auth_service.dart`):

| Platform | Strategy | Implementation |
| --- | --- | --- |
| Web | `webPopup` | Firebase JS SDK popup. |
| Android | `androidCredentialManager` | MethodChannel `com.hyperlocal.app/google_auth` → Credential Manager in `MainActivity.kt`. |
| **iOS** | `firebaseOAuthProvider` | `FirebaseAuth.signInWithProvider(GoogleAuthProvider())` — Firebase's native `OAuthProvider` + `ASWebAuthenticationSession`. |

The Android Credential Manager channel **does not exist on iOS**
(`MissingPluginException`), which is why iOS has its own path. Both paths end in
the same Firebase session and the same ID token, so the backend exchange
(`/shopkeeper/auth/firebase-login`) is untouched.

Two pieces of configuration make the iOS path work:

1. `lib/firebase_options.dart` → `AppFirebaseOptions.iOS` now sets
   `iosClientId` (the project's Google **web** OAuth client — the same value
   Android passes as `serverClientId`) and `iosBundleId` (`com.hyperlocal.app`).
   `firebase_core` forwards them to the native SDK as `CLIENT_ID` / `BUNDLE_ID`
   (`FLTFirebaseCorePlugin.swift`).
2. `ios/Runner/Info.plist` registers the **reversed** client ID
   (`com.googleusercontent.apps.356092661742-hcvah5tufmgv5eas4ao4ijqk0vope50o`)
   as a `CFBundleURLTypes` scheme, so Safari can hand the OAuth result back to
   the app.

## 4. One-time manual step: register the iOS app in the Firebase console

This is the **only** thing that cannot be done from this repository (it needs
console access), and it is required before Google Sign-In or Phone-Auth works on
a device:

1. Firebase console → project `local-pier-506805-g5` → **Project settings →
   Your apps → Add app → iOS**.
2. Bundle ID: **`com.hyperlocal.app`** (must match §1 exactly — case-sensitive).
3. Download **`GoogleService-Info.plist`** and place it at
   `apps/shopkeeper_app/ios/Runner/GoogleService-Info.plist`, then add it to the
   **Runner** target in Xcode (`open ios/Runner.xcworkspace` → drag the file in).
   Commit it alongside `android/app/google-services.json` (both files contain
   only public client configuration).
4. Copy `GOOGLE_APP_ID` from that file into `AppFirebaseOptions.iOS.appId` in
   `lib/firebase_options.dart` (the current value is the project's earlier
   registration and may not match).
5. If the console creates a **dedicated iOS OAuth client**, replace:
   * `CFBundleURLSchemes` in `ios/Runner/Info.plist` with the file's
     `REVERSED_CLIENT_ID`, and
   * `iosClientId` (`AppFirebaseOptions.googleOAuthClientId`) with the file's
     `CLIENT_ID`.

   Keeping the web client ID (today's configuration) is a supported setup and
   requires no change — only do this if you want the iOS-specific client.

## 5. Phone OTP on iOS (future switch — code already in place)

The OTP flow is **not enabled in the MVP** (`kEnabledAuthMethods` = Google only,
`lib/features/auth/domain/auth_methods.dart`); the implementation is ready and
gated behind that single list.

For iOS, `FirebasePhoneOtpService` (`lib/features/auth/data/`) uses
`FirebaseAuth.verifyPhoneNumber` (the `signInWithPhoneNumber` helper is Android
/ web only) and handles all three callbacks — including
`verificationCompleted`, where iOS auto-verifies via a silent APNs push and the
flow finishes without any code entry.

* The reCAPTCHA fallback (used when the silent push is unavailable) needs the
  OAuth URL scheme from §3 — **already registered**, so no extra work.
* Optional: to enable the silent-push path, add the *Push Notifications*
  capability in Xcode and upload an APNs key in Firebase → Project settings →
  Cloud Messaging. Without it, iOS simply falls back to reCAPTCHA + SMS code.

## 6. Google Maps on iOS

`google_maps_flutter` is used by the location picker
(`lib/features/location/.../map_picker_screen.dart`). On iOS the Google Maps SDK
key is provided in code, not in a manifest:

```swift
// ios/Runner/AppDelegate.swift — add when a real key exists
import GoogleMaps
GMSServices.provideAPIKey("YOUR_IOS_MAPS_API_KEY")
```

Currently **no key is configured on either platform** (the Android manifest ships
the placeholder `AIzaSyAAAA…`), and the comment there states that location
detection works without it. The same holds on iOS for GPS capture and geocoding;
only Google map tiles/autocomplete need a real key. This was intentionally left
out because adding Swift code that references a missing key would break the
build.

## 7. Building on macOS

```bash
cd apps/shopkeeper_app
flutter pub get

# Simulator / device run (dev backend over LAN HTTP)
flutter devices
flutter run -d "iPhone 15"          # or a connected device

# Compile without signing (fastest sanity check)
flutter build ios --no-codesign

# Open the Xcode project when you need signing/entitlements
open ios/Runner.xcworkspace

# Release build (needs a signing team in Xcode → Signing & Capabilities)
flutter build ipa --release
```

* `flutter build ios` performs the Xcode build; if Flutter reports a
  CocoaPods-only plugin it will generate `ios/Podfile` — then run
  `cd ios && pod install`.
* Dev backend discovery (`DevBackendDiscovery`) probes the PC's LAN IP; make sure
  the iPhone is on the same Wi-Fi. Cleartext `http://` is allowed for local
  networks via `NSAllowsLocalNetworking` (§2); for a remote/staging backend use
  HTTPS and `--dart-define=API_BASE_URL=https://…`.

## 8. Verification without a Mac

```bash
cd apps/shopkeeper_app
flutter analyze lib test
flutter test test/ios_support_test.dart   # 13 iOS-specific assertions
flutter test                              # whole suite
```

`test/ios_support_test.dart` parses the real `ios/Runner/Info.plist` and
`ios/Runner.xcodeproj/project.pbxproj` and fails if:

* a usage description (camera / location / photo library) disappears or is empty;
* the bundle id stops matching the Android `applicationId`;
* `IPHONEOS_DEPLOYMENT_TARGET` drops below 15.0;
* the reversed OAuth client ID is no longer a registered URL scheme;
* `NSAllowsLocalNetworking` is removed;
* iOS is routed to the Android Credential Manager channel instead of the
  Firebase OAuth provider flow.
