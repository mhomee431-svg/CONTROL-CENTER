23. COVERING / COMPOSITE INDEX STRATEGY
============================================================

Do not randomly create indexes.

For each high-frequency query:

1. Identify WHERE clauses.
2. Identify JOIN columns.
3. Identify ORDER BY.
4. Identify LIMIT.
5. Identify selectivity.
6. Design composite indexes accordingly.

Example conceptual query:

+
inventory availability
+
product variant
+
business location

must be analyzed as a complete query path.

Do not create indexes based only on table columns.

41. DATABASE NORMALIZATION

42. DENORMALIZATION
============================================================

Denormalization is allowed ONLY when:

1. A real query bottleneck exists.
2. Query pattern is well understood.
3. Data synchronization strategy exists.
4. Storage cost is acceptable.
5. It improves measurable performance.

Never denormalize just because it "might be faster."
